# 轮腿机器人 LQR 与 MuJoCo 仿真

对轮腿模型（`urdf/car.xml`）做 LQR 增益计算与 MuJoCo 闭环仿真的代码。

模型本身的权威仓库是 [xinshang555/-urdf-](https://github.com/xinshang555/-urdf-)。
本仓库为**自包含**起见附带了一份 `urdf/car.xml` 与 `urdf/meshes/`（跑仿真所必需），
完整的建模工具链、CAD 导出件、渲染图不在本仓库。

## 坐标系约定

世界系：`+X` 前,`+Y` 侧向,`+Z` 上,重力 `(0,0,-9.81)`。

**侧向轴（髋轴 / 轮自转轴）= 世界 `-Y`。** 有两条独立证据：

1. 4 个 hinge（`hip_lower` / `hip_upper` / `wheel_lower` / `wheel_upper`）
   的世界轴向实测**全部**是 `(0,-1,0)`
2. 轮子绕 `(0,-1,0)` 的转动惯量恰为 25.92 g·mm²（自转轴特征值）

LQR 模型自身的坐标（见 `parameter.py` 头注释）：`X` 前,`Y` **向下**,`Z` 侧向。

## 已定位的问题

### 根因 1：`calculate.py` 的降阶状态退化

`calculate.py` 的状态向量是

```
[x, x', y, y', tl, tl', tr, tr', f, f']
```

把它映射回 MuJoCo 的切空间后，测得 **rank = 7，需要 10**：

```
奇异值: [2.25, 1.73, 1.72, 1, 1, 1, 0.0017, 0, 0, 0]
```

具体退化点：

- `tr` 行与 `tl` 行**逐元素完全相同** —— 两个状态承载同一信息
- `y` 行量级仅 `0.0018` —— 几乎不可观测
- `tl` 在机体俯仰方向上的分量是 `-1.0` —— 即它的「虚拟腿角」
  **主要测的是机身姿态，而不是髋关节角**

后果：该模型有 **3 个**不稳定极点（`50.0 / 45.4 / 12.6` rad/s），
而轮式倒立摆**只有 1 个**。实物实测 `14.15`，只与其中的 `12.6` 对得上（比值 0.89）。
多出的 `45 / 50` 来自把机身高度 `y` 和腿角当作**无界独立自由度** ——
实物里腿是刚性连杆、髋关节还有 ±0.8 rad 硬限位，该自由度并不存在。

用这个 K 上真机，结果是**两个髋关节一起顶到 -0.8 限位**（实测：hips = -0.800，
机身 45°），看着像稳，实际是拄在终点挡块上。

### 根因 2：MuJoCo 线性化含数值假模态

`car.xml` 接触用 `solref=0.002`（很硬）。`mjd_transitionFD` 线性化出来的极点里有
`1e4` 量级的东西。判定它是**数值假象**的证据：

| 检验 | 结果 |
|---|---|
| 极点随差分步长变化 | `eps=1e-8 → 16713`；`eps=1e-5 → 3991` |
| 去掉地面接触 | 该极点**完全消失** |
| 特征向量主分量 | `d_whl_lo`、`d_whl_up`（轮子自转） |

极点随**我自己的差分步长**变化，说明它不是物理。直接喂进 `solve_continuous_are`
得到 `1e7` 量级增益，不可用。

处理方式：用 Schur 分解取慢不变子空间（`design_gain.py`）。
不变性检验 `‖A·Z₁ − Z₁·A_r‖ = 8.06e-08`，增益从 `1e7` 降到 `41`，闭环极点全稳。
**但这仍不足以让真机站住** —— 见根因 3。

### 根因 3：线性化失真（最硬的一块）

在 1° 倾角、零控制下**直接实测**：

```
实测 qacc[wy] = -589.26 rad/s²
物理预测      =   +3.49 rad/s²      （+ω²·θ）
```

差 **169×，且符号相反**。同时 `home` 位姿下 `|qacc| = 699 rad/s²`，
即 home **不是力平衡点**（倒立摆本应如此，符合预期），
但把它当作平衡点做线性化，就是这个失真的来源。

正确做法应是**先辨识真实平衡点**（两轮同时承载、`qacc≈0`）再线性化，
并系统处理接触约束。这比本阶段的工作量大得多。

## 关于 `urdf/car.xml` 的两个建模发现（**未改动该文件**）

这两点建议交给负责建模的同学。

### 1. 轮子 DOF 缺 `armature`

实测：

```
J_axle / J_w = 1834        同样力矩下轮子比机身快 1834 倍
ctrl = 0.001  →  172 rad/s² 的轮加速度
ctrl=1 双轮 0.2 s  →  轮速 34444 rad/s（≈5475 转/秒）
```

`car.xml` 里轮子 `armature=0`、`damping=0`、`frictionloss=0`。
README 说「不要给关节加 damping，轮子必须能自由转」是**对的**，
但 `armature` 是**电机转子惯量**，物理上真实存在，且**不会给轮子刹车** ——
这两者不是一回事。

在仿真脚本里运行时注入 `armature=1e-7`（**未写入 car.xml**）后：
饱和率从 99% 降到 43%，控制器确实能把 5° 拉回 0.16°。

### 2. `home` 位姿只有单轮承载

`home` 关键帧下只有 **2 个接触点，且都在 `geom4` 一个轮子上**，
`wheel_lower` 完全没接触。

几何本身没问题：5 个 geom 均为 mesh、`contype/conaffinity` 一致、
两轮高度实测**同为** `7.973065 mm`。但起始位姿是**单轮承载**，
这会让基于该位姿的线性化偏离真实平衡态。

## 过程中修正过的自身错误（留档，供后续参考）

同一类错误模式犯了三次：**采信的指标 ≠ 想测的东西**。三次都是自检抓回来的。

| # | 当时报的「成功」 | 实际情况 | 暴露它的检查 |
|---|---|---|---|
| 1 | 「稳态倾角 0.79°」 | 机器**躺在地上**，被当成稳态 | 加入机身高度判据 |
| 2 | 「Schur 投影有效」 | 投影用的选择矩阵 `rank=7`，把物理模态一起投影没了 | 加入 rank 检查 |
| 3 | 「`maxp=1.878°`、`xr=0.000 mm` 站住了」 | 打出完整轨迹发现**它在飞**：`t=2.5 s` 时 `z=524 mm`、`x=-3.1 m` | 打出逐点轨迹 |

教训：**判据不可信时，搜索出来的「成功」都是假的。**
接手时若要做参数搜索，应先把「站住」写成可信的判定
（全程 `|pitch| < 5°` 且高度在标称 ±5 mm 且 `|x|` 有界），
并且**先用开环验证该判据会判「失败」**，否则又会自我欺骗。
